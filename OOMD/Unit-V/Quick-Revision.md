# Unit V – Quick Revision

**Class Design, Implementation Modeling and Legacy Systems**

## Important Definitions

| Term | Quick meaning |
|---|---|
| Class Identification | Finding relevant classes from system requirements and scenarios |
| Application Class Model | Static structure of application classes, attributes, operations and relationships |
| Scenario | A specific sequence of actor-system interactions to achieve a goal |
| Data Dictionary | Centralized description of data elements, types, meanings and constraints |
| Package Dependency | Relationship showing that one package depends on another |
| Abstraction | Showing essential features while hiding unnecessary implementation details |
| Design Optimization | Improving performance and efficiency without changing external behaviour |
| Algorithm Design | Developing step-by-step logic for class operations |
| Class Design | Transforming analysis classes into detailed implementation-ready classes |
| Adjustment of Inheritance | Refining superclass-subclass relationships |
| Refactoring | Improving internal code structure without changing external behaviour |
| Reification | Representing complex behaviour or an abstract concept as an explicit class/object |
| Implementation Modeling | Fine-tuning classes, generalizations and associations, followed by testing |
| Reverse Engineering | Analysing existing software to recover its design and structure |
| Wrapping | Providing a new interface around a legacy component |
| Maintenance | Modifying delivered software to correct, adapt or improve it |
