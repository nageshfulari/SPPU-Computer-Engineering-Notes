# Unit VI – Quick Revision
## Testing Framework

**Subject:** Software Testing and Quality Assurance (410245-D) | **SPPU 2019 Pattern**

## 1. Six Sigma
- Data-driven quality methodology used to reduce defects and process variation.
- Characteristics: customer focus, defect reduction, process improvement, data-driven decisions, variation reduction, continuous improvement, employee involvement and measurable results.
- Role in SQA: improves quality, reduces rework/cost, improves testing, customer satisfaction and process efficiency.
- **DMAIC:** Define → Measure → Analyze → Improve → Control.

## 2. Ishikawa's Quality Control Tools
The supplied syllabus heading says seven tools but enumerates eight. Prepare all eight listed entries.

| Tool | Main purpose | Memory keyword |
|---|---|---|
| Flowchart | Shows sequence of process activities and decisions | Process flow |
| Checklist / Check Sheet | Collects, records or verifies information | Recording |
| Pareto Diagram | Ranks problem categories by frequency | Prioritization |
| Histogram | Shows frequency distribution of numerical data | Distribution |
| Run Chart | Displays data over time to show trends | Trend |
| Scatter Diagram | Shows possible relationship between two variables | Correlation |
| Control Chart | Monitors process stability using control limits | UCL / CL / LCL |
| Cause-and-Effect Diagram | Identifies possible causes of a problem | Root cause |

**Key distinctions**
- Flowchart = process steps; Histogram = numerical frequency distribution.
- Histogram = distribution of values; Pareto = categories arranged by descending frequency.
- Run Chart = trends over time; Control Chart = trends plus statistical control limits.
- Scatter Diagram = relationship between two variables.
- Cause-and-Effect = possible causes of a defined problem.

## 3. Total Quality Management (TQM)
- Organization-wide approach to continuously improve products, services and processes.
- Main characteristics: customer focus, continuous improvement, employee involvement, process approach, teamwork, fact-based decisions and management commitment.
- Principles: quality is everyone's responsibility; prevent defects; use facts; communicate; improve continuously.
- Benefits: improved quality, customer satisfaction, lower rework cost, productivity, teamwork and process improvement.

## 4. Maintaining SQA
- Define quality standards.
- Prepare SQA plan.
- Conduct reviews and audits.
- Perform unit, integration, system and acceptance testing.
- Use quality metrics.
- Apply configuration and change management.
- Train and involve employees.
- Analyse recurring defects and continuously improve processes.

## 5. SQA Tasks, Goals and Metrics
**Tasks:** SQA planning, standards definition, reviews/audits, testing, defect tracking, configuration management and reporting.

**Goals:** quality improvement, defect prevention, process compliance, customer satisfaction, cost reduction and continuous improvement.

**Metrics:** defect density, DRE, test coverage, failure rate, rework effort and customer defect rate.

**Formulas**
- Defect Density = Total Defects / Software Size
- Test Coverage = (Items Tested / Total Testable Items) × 100
- DRE = [Defects Removed Before Delivery / (Defects Removed Before Delivery + Defects Found After Delivery)] × 100

## 6. Achieving High Software Quality
**Activities:** requirement analysis → quality planning → design → coding standards/code review → testing → reviews/audits → configuration management → continuous improvement.

**Quality parameters:** functionality, reliability, usability, efficiency, maintainability, portability, security and testability.

## 7. Defect Removal Effectiveness (DRE)
- Measures how effectively defects are removed before delivery.
- E = defects removed before delivery; D = defects found after delivery.
- **DRE = [E / (E + D)] × 100**
- Example: E = 90, D = 10; DRE = [90 / (90 + 10)] × 100 = 90%.
- Higher DRE generally indicates more effective pre-delivery defect removal.

## 8. Run Chart vs Control Chart
- Run Chart: process data over time, often with median reference line; shows trends and shifts.
- Control Chart: process data over time with UCL, CL and LCL; helps assess statistical stability.
- Run Chart is simpler; Control Chart requires statistical control limits.

## 9. Software Maintenance
- Modification of software after delivery to correct defects, adapt to changes, improve functionality or prevent future problems.
- **Corrective:** fixes defects.
- **Adaptive:** adjusts to environment changes.
- **Perfective:** improves features/performance/usability.
- **Preventive:** reduces future risk and improves maintainability.
- Importance: reliability, performance, adaptability, security, user satisfaction, longer useful life and lower future cost.
